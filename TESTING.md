# Validation contract

Run verify.ps1 with MoonBit and Node 24 on PATH (or pass -MoonPath). It formats, generates the public API, checks without warnings, tests WasmGC and JS, rebuilds the shipped engine, then runs demo, CLI, semantic differential, session, malformed-input and benchmark checks. Expected counts and current results are recorded in evidence/unicode-upgrade.json.

The 726 original semantic fixtures are in tools/semantic-cases.py. tools/generate-semantic-oracle.py creates a fresh system Tcl 8.6.15 interpreter per program. Only puts is adapted to collect stdout. Expected results are written to evidence/semantic-reference.json and semantic_oracle_test.mbt. Successful programs compare exact result and output strings; expected errors compare rejection, not wording. The separate legacy generator retains its 248 list/procedure/control cases. Ordinary verification consumes checked-in expected values; regeneration requires the pinned reference version.

New session checks run the real exported module, JSON-lines CLI child processes, and the actual web Worker module through a Node message adapter. Browser acceptance is a separate live CUA run: example, continued state, output before errors, recovery, reset, cancellation, timeout, import/download and mobile layout. Node Worker checks do not stand in for browser acceptance.

The malformed-input corpus remains 307 seeded bounded inputs. Resource experiments and performance measurements are separate evidence; neither is proof of arbitrary hostile-input isolation. The persistent interpreter has no global memory quota.

After the final changes: run the full verifier; regenerate/format/info/build twice and compare source/artifact hashes; bind the evidence manifest to Git blob SHA256s. Reports from older dates are historical. No remote CI, upload, external service, or publication is performed.

For the current optimization regressions, run python tools/generate-semantic-oracle.py cache. This generates 340 independent stateful and arithmetic fixtures in cache_oracle_test.mbt plus evidence/cache-reference.json. Four hand-authored public API tests cover cache clearing, eviction, unchanged execution budgeting and atomic failure of lazy collection mutation. Both oracle groups run through the compiled JS bridge and both MoonBit targets.

To reproduce performance: extract web/engine.mjs from local commit 8c161948071003589cb203f1032e152ee26a1810 into a temporary baseline-engine.mjs using a binary-safe Git subprocess; run python tools/benchmark-semantic.py, then node tools/compare-performance.mjs ABSOLUTE_BASELINE_PATH. The comparison tool rejects a baseline whose SHA256 differs from that Git blob. It alternates engine order, excludes 20 warmups and measures 30 samples for each of seven workloads, checking all results against the independent Tcl output. Timing is evidence, never a CI pass/fail threshold. CPU profile summaries identify allocation and repeated parsing costs, not language coverage.

The semantic-upgrade.json manifest describes the earlier 0.4.0 commit. The 0.5.0 proof checker used performance-upgrade.json; do not apply the older source hashes to the newer tree.

For 0.7.0, python tools/generate-semantic-oracle.py completion generates 321 independent completion fixtures. The return matrix contains 105 code/level/procedure-depth combinations; handler/finally matrices add 72. Normalized matrices remove generated -errorinfo/-errorline/-errorstack, replace error message bodies with a placeholder, recursively normalize -during, and sort dictionary keys. This verifies completion codes, levels, custom options and side effects, not byte-for-byte generated diagnostics. Ten explicit metadata/location programs and 29 native error-message/error-code programs compare selected fields directly. Other cases exercise cleanup, rethrow, variable binding failure, Tcl lexical comparisons and rejection of malformed options. Only the documented subset of native error codes is implemented; generated errorstack uses portable INNER/CALL command frames and is not Tcl bytecode-identical.

Seven new public API regressions cover eval_catch raw levels, snapshots, cleanup chains, cached line locations, budget exhaustion, output/API misuse and portable stack stability. tools/test-completions.mjs runs persistent module sessions, the real JSONL CLI and actual web Worker with a Node message adapter. The live browser report remains separate. eval_catch does not consume a return level, unlike eval. Successful calls clear transient return options; diagnostic globals retain the last error, as in Tcl.

The completion host suite also checks isolated UTF-16 surrogate errors through the legacy text and structured JSON APIs. Script error rendering uses JSON string serialization instead of the Debug formatter, preventing a host panic while preserving code units.

For 0.8.0, python tools/generate-semantic-oracle.py syntax generates 1019 independent programs: eight substitution-flag combinations, exceptional bracket completion versus malformed tails, array-variable parsing boundaries, cross-kind substitutions, option abbreviations, explicit and 400 deterministic generated completeness queries, grouped-word continuation and comment backslash parity. Substitution fixtures compare completion status, normalized error results, side effects and selected options. Completeness results and ordinary successful values/stdout compare exactly. Errors are not a full diagnostic-text equivalence claim.

Live UI acceptance remains separate. info patchlevel identifies this implementation's 0.8.0 version, not a claim to be a native Tcl release.

For 0.9.0, generate-unicode.py verifies the pinned official UnicodeData 16 SHA256 before deriving BMP category intervals and simple case mappings. The imported data and license are under vendor/ucd-16.0.0; no native Tcl lookup tables were copied. audit-unicode.py checks every BMP codepoint against native Tcl 8.6.15, including the public case-conversion byte-width restriction. Its 1048576 property/conversion checks are a data audit, not compiled command coverage.

The 1866 unicode fixtures include 107 batches at generated category boundaries, 75 batches covering all 2369 simple-case entries and exact-nocase search, 840 classification/strict/failure combinations, 284 numeric prefix/range cases, and list failures/options/trim/glob/escapes/UTF-16 operations. Inputs are original, expected results come from a fresh native interpreter per fixture. The boundary selection depends on the source table; expected values do not. Both MoonBit backends and the shipped JS bridge execute these fixtures. Success compares complete result/stdout strings; expected errors compare rejection only.

Five hand-authored API regressions cover isolated-unit roundtrips, local supplementary case preservation, aliased failindex mutation, cached dynamic case input and command/output limits. tools/test-unicode.mjs adds 30 checks across module sessions, the real JSONL CLI and actual Worker, including JSON transport of isolated surrogates. The separate live browser report has 13 input/run/reset and result/output/error checks; it does not rerun import/download, cancellation/timeout or mobile layout.

Reference exclusions are explicit: tools/probe-unicode-reference.py runs risky native inputs in separate subprocesses with timeouts. Three supplementary case conversions exit with Windows access violation 0xC0000005; two trim inputs return truncated UTF-8 exposed by tkinter as surrogateescape bytes. See unicode-reference-limits.json. These five probes are not part of the passing oracle total. Supplementary case conversion in unicode_test.mbt is a local UTF-16 preservation guarantee. Raw Tcl byte-string/object representation parity remains incomplete. Tcl 8.6 category predicates use the low 16 bits of decoded supplementary codepoints, except ascii/xdigit; tests intentionally preserve this reference behavior rather than modern full-plane Unicode semantics.
